## 三、PM的工作流（一个任务从来到走）

```
K哥提需求/PM发现问题
  ↓
【PM·戴全局帽】
  ① 读PRODUCT_VISION + TIMELINE + 病历本
  ② 【派工三问】(见下方)
  ③ 和K哥讨论方案，方案定
  ↓
【PM·写单据A 开发任务书】→ 派开发agent
  ↓
【开发agent】读任务书+PM喂的记忆 → 写代码 → 填单据B返回PM
  ↓
【PM收到B】不碰代码 → 派质检
  ↓
【质检agent】拿代码diff+B → 查bug+查纪律 → 填单据C返回PM
  ↓
【PM看C，做决策】
  - 通过 → commit → 收工
  - 打回 → 写修改指令 → 回到开发agent（最多打回2次，超了找K哥）
```

### ⚠️ 派工三问（PM派开发前的铁律）

```
① 这是老问题还是新问题？→ 查TIMELINE + 病历本
② 如果是老问题：过去成功的解法是什么？走过的弯路有哪些？
③ 把"成功的解法+避开的弯路"喂给开发 → 写进单据A的【必读记忆】
```

## 四、四张交接单据

### 📋 单据A：开发任务书（PM → 开发）
```
【任务】改什么（一句话）
【位置】哪个文件第几行
【要求】改成什么样
【约束】不能碰什么
【必读记忆】PM挑选的相关坑/skill
【验收标准】怎么算改对了
```

### 📋 单据B：代码交付单（开发 → PM）
```
【改了什么】【怎么改的】【为什么这么改】【自测结果】【可能影响】
```

### 📋 单据C：质检报告（质检 → PM）
```
【结论】通过/打回
【必改问题】【建议优化】【纪律检查】
```

## 五、时间线日志纪律

**记录时机**：收尾记 + 重大决策即时记
**格式**：`时间 | 会话 | 涉及问题 | 动作 | 具体内容 | commit | 备注`

---

## 六、病历本纪律

**位置**：`归档/问题档案库/`
**什么时候建**：一个问题反复修2次以上 → 必须建档案
**档案格式**：问题描述 + 根因 + 最终解法 + 走过的弯路 + 代码位置 + commit

---

## 七、Skill生命周期管理

- 废弃的skill**不删**，加废弃声明降级
- 现状变了立刻改skill
- 同一能力一个权威skill

```

□ 6. 本轮有架构变动 → 积木块地图.md已同步？
□ 7. 本地文件已同步服务器？
□ 8. K哥交代的每件事都有交代？
```
